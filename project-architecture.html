System Field Guide / 2026

AI Daily Summary原理与工具交互

一条运行在 macOS 本地的每日知识整理流水线：自动采集工作记录，让大模型完成复盘，沉淀到 Obsidian，再推送至微信公众号草稿箱。

它不是复杂的 Agent 系统

更准确地说，它是一个以 Python 为编排中心，通过本地文件、模型 API 和命令行工具连接起来的自动化 ETL 流程。

03 / TOOLS

每个工具只负责一件明确的事

职责边界越清晰，越容易判断问题发生在哪一层。

T-01

macOS crontab

时间调度器

工作日 18:00 启动 Python 脚本，并把终端输出写入 cron.log。它只决定何时执行，不参与内容处理。

T-02

Python 主程序

流程编排中心

ai_daily_summary.py 连接所有环节：解析日期、加载配置、采集数据、调用模型、写入文件、启动微信脚本和处理异常。

T-03

Day Planner

工作与日记来源

按 {vault}/Day Planners/YYYY-MM-DD.md 精确读取当天文件。全文都会交给模型理解，包括任务、散文记录、产品思考和工具体验。

T-04

Clippings

阅读与网页摘录来源

遍历 {vault}/Clippings/*.md，使用 macOS 文件创建时间筛选当天内容。多个文件以文件名为标题拼接。

T-05

Claude CLI

编码过程来源

从 ~/.claude/projects/**/*.jsonl 读取历史。先按文件修改时间粗筛，再按消息 timestamp 精确筛选；每条最多 2000 字符，每个项目最多 50 条。

T-06

OpenAI Python SDK

统一模型接口

通过不同的 base_url 连接 DeepSeek 或 Kimi。两者兼容 OpenAI API，因此无需维护两套 SDK 集成。

T-07

System Prompt

内容编辑规范

规定“今日概览、工作与行动、阅读与学习、灵感与发现、Claude 对话精华、今日所得”六类内容，也约束语言、列表层级和 Markdown 排版。

T-08

Obsidian

知识存储层

结果保存为 AI Daily-YYYYMMDD.md，附带日期、数据源字符数和生成时间。同一天重复执行会覆盖原文件。

T-09

baoyu-post-to-wechat

微信格式转换与上传

外部 TypeScript 工具负责将 Markdown 渲染成微信 HTML、处理摘要和封面、获取 access token，最终写入公众号草稿箱。

T-10

bun / npx

TypeScript 执行器

Python 无法直接执行 wechat-api.ts，因此优先调用 bun；本机没有 bun 时，退回使用 npx -y bun。

04 / CONFIG

配置文件决定运行方式

config.yaml 把容易变化的连接信息和开关从代码中分离出来。

配置项 控制对象 实际作用
llm_provider 模型选择 在 DeepSeek 和 Kimi 之间切换。
llm.* 模型连接 配置 API Key、base URL 和模型名称。
vault / output_dir 本地文件 指定 Obsidian 数据源根目录与报告输出位置。
max_input_chars 输入规模 限制送入模型的总字符数，默认 60000。
wechat.enabled 发布开关 决定生成报告后是否继续调用微信公众号流程。
wechat.theme / cover 微信外观 设置排版主题和静态封面图片。
05 / FAILURE

故障被分成核心故障和附加故障

是否中断，取决于问题会不会导致报告本身无法生成。

会终止主流程

  • config.yaml 不存在
  • 模型 API Key 未配置
  • LLM API 调用失败
  • 命令行日期格式错误

记录错误后继续

  • 某个数据源不存在或 JSONL 损坏
  • 没有找到 bun、npx 或微信脚本
  • 微信 API 调用失败或超时
  • 封面图不存在
当前实际状态

最近的 LLM 总结和 Obsidian 写入均正常。微信公众号发布返回 40164 invalid ip not in whitelist，说明问题发生在微信平台 IP 白名单层，不是 Python、Markdown 转换或模型调用故障。
